把 1.1.1 发布到 GitHub 的步骤（titargo/-LabelPlus-Moeflow-）
============================================================

准备（本文件夹里已经有了）
  · LabelPlus_Moeflow.zip   —— 更新包，Release 的附件（名字不要改）
  · Version History.txt     —— 更新说明，上传到仓库根目录
  · labelplus_update.xml    —— 已经填好你的仓库，可覆盖到程序目录

第 1 步：给仓库补一个更新说明（可选，但建议）
  1. 打开 https://github.com/titargo/-LabelPlus-Moeflow-/upload/main
  2. 把本文件夹里的 Version History.txt 拖进去
  3. 点 Commit changes

第 2 步：发布 Release（必须）
  1. 打开 https://github.com/titargo/-LabelPlus-Moeflow-/releases/new
  2. Choose a tag 输入：v1.1.1
     选择 “Create new tag: v1.1.1 on publish”
  3. Release title 填：1.1.1
  4. 把 LabelPlus_Moeflow.zip 拖到下方的附件区
     （附件名必须是 LabelPlus_Moeflow.zip）
  5. 不要勾 “Set as a pre-release”
  6. 点 Publish release

  发布后检查：
  https://github.com/titargo/-LabelPlus-Moeflow-/releases/download/v1.1.1/LabelPlus_Moeflow.zip
  这个地址应该能直接下载到 zip。

第 3 步：配置客户端
  把 labelplus_update.xml 复制到程序目录（和 LabelPlus_Moeflow.exe 放一起），
  或者自己确认里面是：

    <Owner>titargo</Owner>
    <Repo>-LabelPlus-Moeflow-</Repo>
    <Branch>main</Branch>
    <VersionFile>version.txt</VersionFile>

第 4 步：测试更新
  用 1.1.0 的客户端 → 帮助 → 检查更新
  应该显示“发现新版本 1.1.1”，点“下载并安装”，
  程序会自动替换文件并重启，重启后标题是 1.1.1。

以后发新版（例如 1.1.2）
  1. 改源码版本号并重新编译
  2. 打出新的 LabelPlus_Moeflow.zip
  3. 新建 Release，tag 写 v1.1.2，上传同名 zip，发布
  4. 把仓库里的 version.txt 改成 1.1.2，Commit
  5. 客户端下次检查就会提示更新

常见问题
  · 404：仓库名/分支/路径不对；仓库必须是 Public
  · 提示没有更新包：Release 里没传 zip，或 tag/附件名与 ZipUrl 不一致
  · 改了 version.txt 没反应：raw.githubusercontent.com 有几分钟缓存
  · 更新失败：程序目录要可写，不要放在 Program Files 下
